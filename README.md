# GridGaurd

**GNN-based power grid failure prediction with explainable AI and interactive scenario analysis.**

---

## What Is GridGaurd?

Power grids are complex systems where a local fault can cascade into a widespread blackout. GridGaurd treats a power grid as a graph — buses as nodes, transmission lines as edges — and uses a **Graph Neural Network (GraphSAGE)** to estimate per-node failure risk.

The goal is not to replace traditional power flow solvers, but to provide a **fast, graph-aware screening layer** for monitoring and what-if analysis. Every prediction comes with a human-readable explanation of which features drove the risk score.

---

## Features

- **Node-level risk prediction** — each bus gets a risk score (Low / Medium / High) and a Safe / Failure-prone label
- **Scenario stress testing** — apply load increases and voltage drops to see how grid risk shifts
- **Gradient-based explanations** — feature attribution (voltage, load, degree) per node via GNNExplainer or gradient fallback
- **Multiple grid support** — IEEE 14, IEEE 30, IEEE 118, PGLib 118, PGLib 300
- **FastAPI backend** — REST API for inference, scenarios, and explanations
- **Interactive browser UI** — canvas-rendered topology with risk coloring and scenario controls

---

## How It Works

```
MATPOWER .m file  →  Build graph (nodes = buses, edges = lines)
                  →  Node features: voltage magnitude, load, node degree
                  →  Labels: voltage violation rule (|V| < 0.95 or > 1.05 pu)
                  →  Train GraphSAGE on 5 grid cases
                  →  Inference → per-node risk scores
                  →  Explanation → gradient attribution per feature
```

### Model Architecture

A two-layer **GraphSAGE** network:

```
Input features (3)  →  SAGEConv(3→32)  →  ReLU
                    →  SAGEConv(32→16) →  ReLU
                    →  Linear(16→2)    →  [Safe, Failure-prone]
```

Trained jointly across all five grid cases (IEEE 14 / 30 / 118, PGLib 118 / 300) with an 80/20 train/test split per graph, using Adam optimizer and cross-entropy loss for 100 epochs.

## API Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/` | Health check |
| `GET` | `/predict/{grid_name}` | Run inference on a grid |
| `GET` | `/predict_scenario/{grid_name}?load_factor=&voltage_drop=` | Stress scenario prediction |
| `GET` | `/explain/{grid_name}/{node_id}` | Feature attribution for a node |

**Supported grid names:** `ieee14`, `ieee30`, `ieee118`, `pglib118`, `pglib300`

### Example

```bash
# Baseline prediction
curl http://localhost:8000/predict/ieee14

# Stress scenario: 20% more load, 5% voltage drop
curl "http://localhost:8000/predict_scenario/ieee14?load_factor=1.2&voltage_drop=0.95"

# Explain node 5
curl http://localhost:8000/explain/ieee14/5
```

## Setup & Usage

### Prerequisites

- Python 3.9+
- PyTorch
- PyTorch Geometric
- FastAPI + Uvicorn

### Install

```bash
pip install torch torch-geometric fastapi uvicorn
```

### Run the full pipeline

```bash
# Step 1 — Build graphs from MATPOWER files
python Scripts/Build_graph.py

# Step 2 — Train the GNN
python Scripts/Train_GNN.py

# Step 3 — Start the backend
cd Backend
uvicorn app:app --reload --port 8000

# Step 4 — Open the frontend
# Open Frontend/index.html in your browser
```

## Explanation System

GridGaurd explains each prediction using gradient-based feature attribution:

1. **Primary method:** GNNExplainer (PyG new or legacy API)
2. **Fallback:** Gradient × Input attribution

For each node, the explanation includes:
- Normalized importance score per feature (voltage, load, degree)
- Human-readable text (e.g., *"Low voltage (0.91 pu) was the primary contributor — importance: 62%"*)

---

## Data & Labels

- **Input:** MATPOWER `.m` files (IEEE and PGLib test cases)
- **Node features:** voltage magnitude (pu), active load (normalized), node degree
- **Labels:** rule-based — a node is labeled *failure-prone* if its voltage violates the 0.95–1.05 pu standard operating band

---

## Limitations

- Labels derive from a voltage threshold rule, not real outage data
- Intended for research and demo use — not operational dispatch
- Model quality is bounded by the size and diversity of available grid cases
